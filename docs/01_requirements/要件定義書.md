## 2. プロジェクト概要

- クライアント: EIAI TEC(個人事業主)
- プロジェクトタイプ: 個人事業主のコーポレートサイト(LP)新規構築。既存の静的モックアップ(`mockup/index.html`)をNext.jsで実装し、お問い合わせフォームの実送信化・モバイル対応・画像最適化・SEO仕上げを行った上で本番公開する案件。
- 体制: 発注者=受注者=クライアント本人によるソロプロジェクト。Claudeと対話しながら進めるCoachingモードで進行する(`docs/00_overview/進行モード.md`)。

## 3. 背景・目的

- EIAI TECは非IT企業向けのAI業務支援・コンサル(特に「業務自動化・ツール開発」)を行う個人事業主であり、実績ゼロの状態から、まず自社(屋号)の公式サイトを構築することが本プロジェクトの出発点である(プロジェクト計画書2章)。
- 第1弾の実績として、本サイト自体のAI駆動開発プロセス(要件定義〜デプロイ)を「メタ事例」としてPortfolioセクションに掲載する方針が既に確定している。「このサイト自体がAI駆動開発で作られている」ことを事業内容(AI活用支援)の実証とする狙いがある(site-direction.md §2、プロジェクト計画書2章)。
- サイトの方向性・デザイントークン・コピー・レイアウトは既にヒアリングとモックアップ検討を経て確定済みであり(site-direction.md §10、`mockup/index.html`)、本要件定義書は、この確定済みモックアップを実際に公開可能なNext.jsサイトとして実装するための機能要件を確定するものである。

## 4. 用語集(クライアント目線)

| 用語 | 説明 |
|---|---|
| LP(ランディングページ) | 訪問者が最初に見る1枚もののトップページ。本サイトではHero/Services/Portfolio/About/Contactの5セクションで構成される。 |
| Next.js(App Router) | 本サイトの実装に使うWebサイト構築の仕組み(フレームワーク)。ページの表示速度や検索エンジン対応に強い。 |

| favicon | ブラウザのタブなどに表示される小さなサイトアイコン。 |

| Vercel | 本サイトの公開(デプロイ)に使うホスティングサービス。 |
| 独自ドメイン | `eiaitec.jp`のような、Vercelの仮アドレスに代わる本番公開用の固有URL。 |

## 5. スコープ

### 5.1 フェーズ1(今回のイテレーションで扱うこと)

プロジェクト計画書5.1章に基づき、以下を対象とする。

- LP(Hero / Services / Portfolio / About / Contact)を`mockup/index.html`を正としてNext.js(App Router)で実装する。
- お問い合わせフォームをResendを使って実送信化する(受信先アドレス確定済み。詳細は6.6・7章、要確認事項は10章参照)。
- モバイル環境でも機能するナビゲーションメニューを実装する。
- base64埋め込みの画像を実ファイル化し、`next/image`で最適化する。
- SEO/OGPメタ情報・favicon・動的コピーライト年など、公開サイトとして最低限必要な仕上げを行う。
- Vercelへデプロイし、公開直前に独自ドメイン(`eiaitec.jp`)を取得してDNS設定する。
- 要件定義書・機能仕様書・基本設計書・詳細設計書・テスト結果報告書を、開発プロセス自体をポートフォリオのメタ事例として見せられる形で整備する(本書はそのうちの要件定義書に相当する)。

### 5.2 フェーズ2以降(今回対象外)

プロジェクト計画書5.2章に基づき、以下は今回のイテレーションでは扱わない。

- 実績専用ページ(一覧+詳細構造)の実装。当面はLPの`#portfolio`セクション内(メタ事例1件)で完結させる。実際のクライアント案件が増えた段階で、次イテレーション以降に着手を検討する(着手タイミングは10章の要確認事項を参照)。
- SNS等の外部発信チャネル(X、note等)の開設・連携。
- 多言語化対応(日本語のみを維持)。
- `.com`ドメインの取得可否検討(今回スコープ外。ドメイン取得作業時またはそれ以降の判断事項とする。10章参照)。

## 6. 機能要件

各機能は「〜できる」形式で記述する。機能ID(F-01〜F-11)は機能仕様書と相互参照する。

### 6.1 F-01: ヘッダー・グローバルナビゲーション(PC表示)

- 訪問者は、ページ上部に常に表示されるヘッダーから、「サービス」「実績」「EIAI TECとは」の各セクションへワンクリックで移動できる。
- 訪問者は、ヘッダー右の「お問い合わせ」ボタンから、Contactセクションへ直接移動できる。
- 訪問者は、ヘッダー左のロゴ(アイコン+「EIAI TEC」の文字)をクリックすると、ページ最上部(Hero)に戻れる。
- 入力: 訪問者によるナビゲーションリンク/ロゴのクリック操作。
- 処理: クリックされたリンク先のページ内アンカーへスクロール移動する。
- 出力: 該当セクションが画面に表示される。

### 6.2 F-02: ヒーローセクション

- 訪問者は、サイトを開いた直後に、キャッチコピー「AI(人工知能)とEI(感性)で働き方をアップデート。」とリード文「EIAI TECは、AIの力でお客様の業務効率化を支援します。」を確認できる。
- 訪問者は、「相談してみる」ボタンからContactセクションへ、「実績を見る」ボタンからPortfolioセクションへ移動できる。
- 入力: なし(静的コンテンツの表示)。ボタンクリック時のみ操作入力あり。
- 処理: 確定済みコピー(`mockup/index.html`のHero部分)をそのまま表示する。
- 出力: Heroセクションの表示、ボタンクリック時は該当セクションへの遷移。

### 6.3 F-03: Servicesセクション

- 訪問者は、EIAI TECの事業内容が「業務自動化・ツール開発」であることを、リード文で確認できる。
- 訪問者は、「課題の棚卸し」「ツール開発」「導入・定着」の3項目について、それぞれタグ・見出し・説明文の形式で内容を確認できる。
- 入力: なし(静的コンテンツの表示)。
- 処理: 確定済みコピー(`mockup/index.html`のServices部分、site-direction.md §10)をそのまま表示する。
- 出力: Servicesセクションの表示。

### 6.4 F-04: Portfolioセクション

- 訪問者は、見出し「実績」の下に、メタ事例(CASE/000「EIAI TEC 公式サイトの構築」)を1件確認できる(番号ルール・将来の複数事例表示は10章No.15参照)。
- 訪問者は、ステータスタグ「Webサイト」(事例の分野・種別を日本語でわかりやすく示すタグ。2026-09-09改訂、旧「SELF-BUILT · META CASE」から変更)、事例の説明文、4つの構築ステップ(01方向性のヒアリング〜04本実装・デプロイ)、フッター注記「今後、実際のクライアント案件を随時追加予定です。」を確認できる。
- 実績が複数件になった場合の一覧・詳細ページ化は、今回のスコープに含まない(5.2参照)。
- 入力: なし(静的コンテンツの表示)。
- 処理: 確定済みコピー(`mockup/index.html`のPortfolio部分)をそのまま表示する。
- 出力: Portfolioセクションの表示。

### 6.5 F-05: Aboutセクション

- 訪問者は、見出し「EIAI TECとは」と、大きく表示されたロゴアイコンを確認できる(ナビゲーション上の表記は「屋号について」のまま)。
- 訪問者は、EIAI TECの事業内容とスタンスについて、本文で確認できる(段落数について要確認事項あり。10章参照)。
- 代表者個人の氏名・顔写真・経歴は表示しない(site-direction.md §5)。
- 入力: なし(静的コンテンツの表示)。
- 処理: 確定済みコピー(`mockup/index.html`のAbout部分)をそのまま表示する。
- 出力: Aboutセクションの表示。

### 6.6 F-06: Contactセクション表示

- 訪問者は、見出し「お問い合わせ」と説明文「業務の自動化やAI活用について、まずは現状の課題からご相談ください。」を確認できる。
- 訪問者は、「ご相談の流れ」として「フォーム送信後、担当より通常2営業日以内にメールでご返信します。まずは概要の共有だけで構いません。」という案内を確認できる。
- 入力: なし(静的コンテンツの表示)。
- 処理: 確定済みコピー(`mockup/index.html`のContact部分)をそのまま表示する。
- 出力: Contactセクションの表示、および6.7のお問い合わせフォーム。

### 6.7 F-07: お問い合わせフォーム送信(Resend連携)

- 訪問者は、「会社名・屋号」「お名前」「メールアドレス」「ご相談内容」の4項目を入力し、「送信する」ボタンでお問い合わせを送信できる。
- クライアント(EIAI TEC本人)は、訪問者からのお問い合わせ内容を、指定の受信用メールアドレス宛のメールで受け取れる。
  - 受信(送信先)メールアドレス: `[CONTACT_RECEIVE_EMAIL]`(確定済み。オーケストレーターからのヒアリング結果に基づく。実アドレスは個人情報のため本ドキュメントには記載しない。実装フェーズでは環境変数として`.env.local`等のGit追跡対象外ファイルで管理する。実アドレスはクライアント本人が把握済み)。
  - 送信元メールアドレス: 独自ドメイン(`eiaitec.jp`)取得前は、Resendの検証済みテストドメイン(例: `onboarding@resend.dev`等)を暫定的に使用する想定(確定済み方針)。ただし、Resendのサンドボックス制限を踏まえた技術的な実現可否・具体的な運用方法は未確定であり、要確認事項とする(10章参照)。
- 訪問者は、送信後に送信結果(成功/失敗)が分かる状態で画面上のフィードバックを受け取れる(具体的な表示文言は未確定。10章参照)。
- 各入力項目の必須/任意の別、入力形式のチェック内容(文字数上限等)、スパム対策の要否、送信者への自動返信の要否は未確定であり、要確認事項とする(10章参照)。
- 入力: 会社名・屋号(任意/必須は要確認)、お名前、メールアドレス、ご相談内容。
- 処理: 入力内容を検証(バリデーション内容は要確認)した上でResend経由でメール送信を実行する。
- 出力: 指定の受信用メールアドレスへのメール送信、および訪問者への送信結果フィードバック。

### 6.8 F-08: モバイル用ナビゲーションメニュー

- 現状のモックアップでは、画面幅640px以下でヘッダーのナビゲーション(サービス/実績/EIAI TECとは)が非表示になるのみで、代替の操作手段がない(プロジェクト計画書3章・7章)。
- スマートフォン等の狭い画面で閲覧する訪問者は、ハンバーガーメニュー等の代替手段によって、ヘッダーの各ナビゲーションリンク(サービス/実績/EIAI TECとは/お問い合わせ)へアクセスできる。
- メニューを開いた訪問者は、リンクをタップすることで該当セクションへ移動し、メニューが自動的に閉じる。
- 入力: メニュー開閉ボタン・ナビゲーションリンクのタップ操作。
- 処理: メニューの開閉状態を切り替え、リンクタップ時は該当セクションへスクロール移動してメニューを閉じる。
- 出力: モバイル用メニューの表示/非表示、該当セクションへの遷移。
- 具体的な意匠(アイコンの形状、開閉アニメーション等)は`mockup/index.html`に定義がないため、設計フェーズでsite-direction.mdのデザイントークンに沿って検討する。

### 6.9 F-09: 画像実ファイル化・next/image最適化

- 訪問者は、現状base64埋め込みで表現されている画像(ロゴ、ヒーロービジュアル、セクション装飾アイコン等、計7箇所)を、実ファイル化・最適化された画像として、従来と同等の見た目で閲覧できる。
- クライアントは、`images/`フォルダに用意済みの画像素材(`icon.png`、`work.png`、`worker1.png`、`worker2.png`、`worker3.png`)が実装時の画像ソースとして使われることを確認できる。各画像とページ内の表示箇所(スロット)との対応関係は設計フェーズで確定する(10章参照)。
- 入力: `images/`フォルダの画像ファイル。
- 処理: `next/image`コンポーネントによる画像の自動最適化(サイズ別配信・遅延読み込み等)を行う。
- 出力: 最適化された画像がページ内の各所に表示される。

### 6.10 F-10: SEO/OGP・favicon・動的コピーライト年

- 検索エンジンやSNSでサイトが共有された際、クライアントが意図したタイトル・説明文・OGP画像が表示される状態にできる(具体的な文言は未確定。ドラフト案は機能仕様書に記載し、最終確定はクライアント確認事項とする。10章参照)。
- 訪問者は、ブラウザのタブ等でEIAI TECのfaviconを確認できる(使用素材は未確定。10章参照)。
- 訪問者は、フッターの著作権表示(現状モックアップでは「© 2026 EIAI TEC. All rights reserved.」で固定表示)が、閲覧時点の年に自動的に切り替わる状態で表示されるのを確認できる。
- 入力: なし(ビルド/実行時に自動生成)。
- 処理: メタタグの出力、favicon配信、現在年を取得しての著作権表示の生成。
- 出力: `<head>`内のSEO/OGPタグ、favicon、動的な著作権年表示。

### 6.11 F-11: Vercelデプロイ・独自ドメイン設定

- クライアントは、開発中の状態をVercelの仮ドメインで随時確認できる。
- クライアントは、公開直前のタイミングで独自ドメイン`eiaitec.jp`を取得し、Vercelに設定した上で本番公開できる。
- 独自ドメイン取得後、Resendの送信元ドメイン設定(SPF/DKIM等)を独自ドメインへ切り替える必要がある可能性がある(プロジェクト計画書7章)。切り替えの要否・手順は設計フェーズで確定する。
- 入力: なし(運用・設定作業)。
- 処理: Vercelへのデプロイ、DNS設定、ドメイン紐付け。
- 出力: 独自ドメインでアクセス可能な本番サイト。

## 7. 非機能要件

- パフォーマンス: `next/image`による画像最適化を行い、モックアップと同等以上の表示速度を目指す(具体的な数値目標の記載は一次情報になし)。
- レスポンシブ対応: PC・タブレット・スマートフォンなど画面幅の異なる端末で閲覧可能な状態にする。現行モックアップの640pxブレークポイントを踏襲しつつ、モバイルナビ(6.8)を追加する。
- 可用性: Vercelのホスティング基盤を利用し、常時アクセス可能な状態を維持する。個人事業主のソロ運用のため、SLA等の具体的な可用性目標は定めない。
- セキュリティ: Vercelの標準機能によりHTTPS配信とする。お問い合わせフォームのスパム対策(reCAPTCHA等)の要否は未確定(10章参照)。
- アクセシビリティ: `mockup/index.html`で装飾画像に空のalt属性、ロゴ画像に「EIAI TEC」のalt属性を設定する等、基本的な配慮が既になされている。実装時もこれを踏襲する。網羅的なアクセシビリティ基準(WCAG等)への準拠は、一次情報に明記がないため今回のスコープとしない。
- デザイン・コピーの一貫性: `mockup/index.html`および`site-direction.md`§6(デザイントークン)・§10(モックアップ確定内容)を正とし、実装フェーズで新たなデザイン変更は行わない(プロジェクト計画書6章)。
- 保守性: 「このサイト自体がAI駆動開発の実績である」というメタ事例方針(2章)を踏まえ、後に一般公開・引用される可能性を考慮し、可読性の高いソースコード構成・ドキュメント整備を意識する。

- 納期: 一次情報に具体的な数値の記載なし。固定の納期指定なし(プロジェクト計画書6章)。超過という概念自体が本プロジェクトには該当しない。
- 体制: 発注者=受注者=クライアント本人(個人事業主のソロプロジェクト)。Claudeと共に学びながら進めるCoachingモードで進行する(`docs/00_overview/進行モード.md`)。
- 実装技術: Next.js(App Router)固定(site-direction.md §7、プロジェクト計画書6章で確定)。
