# EIAI TEC Webサイト方向性

最終更新: 2026-09-09(CASEステータスタグの日本語化に伴い更新)

## 1. コンセプト

- 屋号: EIAI TEC(個人事業主)
- 事業内容: 非IT企業向けのAI業務支援・コンサル。特に「業務自動化・ツール開発」を中心サービスに据える。
- サイトの目的(優先順): ①実績・信頼の可視化 ②知見・発信の場 ③名刺代わりの存在証明。問い合わせ獲得は結果として発生すればよい位置づけで、最優先のKPIではない。
- ターゲット: 非IT企業全般。業種・企業規模は現時点であえて絞らない。
- トーン&マナー: フォーマルな企業サイト風。個人の顔は出さず、屋号としての信頼感を優先する。
- 言語: 日本語のみ(将来の多言語化は現時点で考慮しない)。

## 2. ポートフォリオの考え方

- 現時点では実績ゼロからのスタート。
- **第1弾の事例として、本Webサイト自体のAI駆動開発プロセスをメタ事例として公開する。**
  - 要件定義→設計→実装→デプロイの過程を、実績として見せられる形に整理する。
  - 「このサイト自体がAI駆動開発で作られている」ことが、事業内容(AI活用支援)の実証になる。

## 3. サイト構成

- LP(トップページ1枚)+ ポートフォリオ専用ページ、の2階層構成。
- LPに含めるセクション(モックアップで確定):
  1. ヒーロー(屋号・キャッチコピー・CTA)
  2. Services(事業内容/サービス。業務自動化・ツール開発を中心に)
  3. Portfolio(実績。当面はメタ事例1件のみ)
  4. About(屋号紹介。最小限のプロフィール、屋号名のみ)
  5. Contact(お問い合わせフォーム)
  - ※「選ばれる理由・強み」セクションはモックアップ検討の過程で不要と判断し廃止。強みはServices/Portfolioの記述内で示す。
- ポートフォリオページ: 事例カード形式。将来の追加を見越して一覧+詳細の構造にしておく。
- 詳細な確定コピー・レイアウトルールは「10. モックアップ確定内容」を参照。

## 4. お問い合わせ

## 5. プロフィール開示範囲

## 6. デザイントークン

### カラー

ロゴから抽出したメインオレンジ `#FC6A02` は彩度・輝度が高すぎるため、フォーマルな企業サイト向けに沈めたトーンへ調整する。

| 用途 | Hex | 備考 |
|---|---|---|
| Primary(基調オレンジ) | `#D6681F` | ロゴの色相(H≈25°)を保ったまま彩度・明度を落とした落ち着いたオレンジ |
| Primary Dark(hover/強調) | `#B8551A` | ボタンhover、強調テキスト等 |
| Primary Tint(淡い背景・タグ) | `#FBEAE0` | セクション背景、バッジ背景等 |
| ロゴ本来の色(参考・ロゴ表示専用) | `#FC6A02` | ロゴ画像自体はそのまま。UI全体には使わない |
| Base白 | `#FFFFFF` | 背景 |
| テキスト(濃) | `#1F1B18` | 温かみのある黒(オレンジと調和) |
| テキスト(淡・補助) | `#6B6560` | 補足テキスト・キャプション |
| 区切り線(通常) | `#E7DFD6` | セクション内の細い区切り線 |
| 区切り線(強調) | `#C7B9A9` | ヘッダー下・セクション間の区切りなど、視認性を上げた境界線 |
| モノスペースタグ用グレー | `#9A8F82` | CASE番号など補助的なmonoテキスト |

いずれもダークモード用の対応色をCSS変数として用意済み(`mockup/index.html`の`:root`参照)。

### フォント

- 日本語: **Noto Sans JP**
- 欧文・数字: **Inter**
- 無料・視認性が高く、多くの企業サイトで実績のある組み合わせ。ロゴの幾何学的で太いゴシック体の雰囲気とも相性が良い。
- 補助(タグ・CASE番号などの小さなラベル): **IBM Plex Mono** — 「構築ログ」的なエンジニアリングの信頼感を出すアクセントとして、モックアップ検討時に追加。本文には使わない。

### Portfolio

- 見出し「実績」のみ(説明文なし)
- メタ事例カード1件: `CASE / 000`「EIAI TEC 公式サイトの構築」、ステータスタグ `Webサイト`(事例の分野・種別を日本語でわかりやすく示す。英語表記の「SELF-BUILT · META CASE」から変更。2026-09-09改訂)

  - 複数事例表示時の方針(2026-09-09確定): 事例が2件以上になった場合はカードを横方向にスライド(カルーセル)させる表示形式を想定する。実装の詳細は実績専用ページ化(§3で将来検討としている一覧+詳細構造)に着手する際にあわせて設計する。
  - 本文: 本サイト自体をAI駆動開発プロセスに沿って構築している旨
  - 4ステップ: 01 方向性のヒアリング → 02 デザイン方針策定 → 03 静的モックアップ確認(本ページ) → 04 本実装・デプロイ

### レイアウトルール

- Services / Portfolio / About / Contact の見出しブロックは共通コンポーネント化(`section-head--stack`: eyebrowを見出しの上にスタック表示)。Heroのみ独自レイアウト。
- 各セクションのeyebrow文字サイズは、対応する見出しの表示幅に一致するよう動的に調整(JSで計測・適用)。かつ上記4セクションのeyebrowは互いに同じ文字サイズになるよう揃える。
- セクション間の区切り線は「区切り線(強調)」トークンで統一。
