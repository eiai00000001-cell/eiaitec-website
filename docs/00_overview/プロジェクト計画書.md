## 2. 案件概要

- クライアント: EIAI TEC(個人事業主)
- 事業内容: 非IT企業向けのAI業務支援・コンサル。特に「業務自動化・ツール開発」を中心サービスとする(site-direction.md §1)。
- 依頼の背景・経緯:
  - 実績ゼロからのスタートにあたり、まず自社(屋号)の公式サイトを構築する(site-direction.md §2)。
  - 第1弾の実績として、本サイト自体のAI駆動開発プロセスを「メタ事例」としてポートフォリオに掲載する方針(site-direction.md §2)。「このサイト自体がAI駆動開発で作られている」ことを事業内容(AI活用支援)の実証とする狙いが明記されている。
  - サイトの方向性・デザイントークン・コピー・レイアウトは既にヒアリングとモックアップ検討を経て確定済み(site-direction.md §10、`mockup/index.html`)であり、本プロジェクトはこの確定済みモックアップをNext.jsで実装し、公開まで持っていく工程を扱う。
- 本プロジェクトの位置づけ: 個人事業主のソロプロジェクト。固定の発注者・受注者関係ではなく、Claudeと対話しながら学習を兼ねて進めるCoachingモードで進行することが既に確定している(進行モードの詳細は別途 `docs/00_overview/進行モード.md` にて整理予定)。

## 3. 目指すゴール

一次情報から読み取れる、本イテレーションで目指す状態は以下の通り。

- モックアップ(`mockup/index.html`)で確定した見た目・コピーを、実際に公開可能なNext.jsサイトとして実装する。
- お問い合わせフォームが実際にメール送信できる状態にする(現状はモックのみで送信不可)。
- モバイル環境でもナビゲーションが機能する状態にする(現状640px以下でnavが消えるだけで代替導線がない)。
- 画像をbase64埋め込みから実ファイル化し、`next/image`による最適化を行う。
- SEO/OGP・favicon・動的コピーライト年など、公開サイトとして最低限必要な仕上げを行う。
- Vercelへデプロイし、公開直前に独自ドメイン(`eiaitec.jp`)を取得・設定して本番公開する。
- 開発プロセス自体(要件定義〜テスト結果報告)をドキュメントとして整備し、「このサイト自体がAI駆動開発の実績である」ことを裏付けられる状態にする(site-direction.md §2のメタ事例方針に基づく)。

これらは「サイトを見た目通りに動く状態で世に出す」ことがゴールであり、実績専用ページの拡張やSNS発信チャネルの整備など、事業の発信力そのものを広げる部分は今回のスコープには含まれない(詳細は5章)。

## 4. 進め方

- 本プロジェクトは以下の6フェーズで進める: 計画 → 要件定義 → 設計 → 実装 → テスト → 納品。
- 初回イテレーション(本イテレーション)は、上記6フェーズをウォーターフォール的に一気通貫で実施する。
  - 計画: 本書の作成(現在フェーズ)。案件全体の目的・スコープの大枠を整理する。
  - 要件定義: analystが本書を土台に、LP実装・フォーム送信・モバイルナビ・画像最適化・SEO仕上げ・デプロイ/ドメインなど各機能の詳細要件を確定する。
  - 設計: 基本設計書・詳細設計書を整備する(site-direction.mdのデザイントークン・コンポーネント方針を踏まえる)。
  - 実装: Next.js(App Router)での実装、Resend連携、画像最適化などを行う。
  - テスト: 動作確認・テスト結果報告書の作成。
  - 納品: Vercelへのデプロイ、独自ドメイン設定、公開。
- 2巡目以降(次のイテレーション以降)は、実績専用ページの追加やSNS連携など個別の機能追加テーマごとに、同じ6フェーズを短いサイクルでループするアジャイル的な進め方を想定する。各イテレーションの開始時に本書を改訂し、Notion側のチケットで管理する運用を原則とするが、**本案件では現時点でNotion連携を行わない**(詳細は9章)。
- 想定スケジュール感: 一次情報に具体的な納期・スケジュールの記載はない。個人事業主のソロプロジェクトであり、固定の納期は定めない(6章参照)。

## 5. やること/やらないこと

### 5.1 今回のイテレーションで扱うこと

- LP(Hero / Services / Portfolio / About / Contact)をNext.js(App Router)で実装し、`mockup/index.html`を正として移植する。
- お問い合わせフォームをResendを使って実送信化する。
- モバイル用ナビゲーションメニューを実装する。
- base64埋め込みの画像を実ファイル化し、`next/image`で最適化する。
- SEO/OGPメタ情報・favicon・動的コピーライト年など基本的な仕上げを行う。
- Vercelへデプロイし、公開直前に独自ドメイン(`eiaitec.jp`)を取得してDNS設定する。
- 要件定義書・機能仕様書・基本設計書・詳細設計書・テスト結果報告書を、この開発プロセス自体をポートフォリオのメタ事例として見せられる形で整備する。

機能ごとの詳細な要件(フォームのバリデーション仕様、SEOタグの具体値、デプロイ手順の詳細など)は、この計画書では確定せず、後続のanalystによる要件定義書で確定する。

### 5.2 やらないこと・対象外・将来検討

- 実績専用ページ(一覧+詳細構造)の実装。site-direction.md §3では将来的にポートフォリオページを一覧+詳細構造にする方針が示されているが、現状メタ事例1件のみのため、今回はLPの`#portfolio`セクション内で完結させる。次イテレーション以降、実績が増えた段階で対応する。
- SNS等の外部発信チャネル(X、note等)の開設・連携。site-direction.md §9でも未決事項として明記されている。
- 多言語化対応(site-direction.md §1で将来検討外と明記)。

## 7. リスク・懸念事項

- ドメイン取得を公開直前まで先送りする方針のため、取得タイミングで希望ドメイン(`eiaitec.jp`)が既に取得されている、または想定外に手続きが長引くと公開スケジュールに影響する可能性がある。
- Resendでのメール送信実装には送信元ドメインの認証設定(SPF/DKIM等)が必要になる可能性があり、独自ドメイン取得前は暫定的な送信元設定での運用となる見込み。ドメイン確定後の設定切り替えが必要になる可能性がある(要確認事項として8章に記載)。
- base64埋め込み画像の実ファイル化にあたり、元画像の解像度・品質が最適化後の表示に耐えるか未確認。
- 「このサイト自体をポートフォリオのメタ事例として見せる」という方針上、開発ドキュメント(要件定義書等)の記述レベルや粒度が、後に一般公開・引用される可能性を考慮したものになっているか、要件定義以降で継続的に意識する必要がある。
